# 开发依赖与资料清单

本项目面向已完成厂商驱动适配的天准 N10，包含三相机混合采集及独立的单 ZED + IMU 工具。完整部署依赖匹配的 BSP、厂商运行库和开发资料，不能仅克隆源码即在空白设备运行。

## 设备与系统基线

| 项目 | 已使用的配置 |
| --- | --- |
| 板型 | 天准 N10 `B25EJ21_007 R1.1`，aarch64 |
| 系统 | 厂商 `6.8.12-rt-tegra`，L4T R38.2 / JetPack 7.0 |
| 内核包 | `rb-jetson-firmware-kernel-rt-jp7.0-ga`，1.3.3 |
| 原 S56 设备树包 | 1.4.1，`AGI_B25EJ21_007_r1_1_JP7.0_ga_v1.4.1_S56`；当前运行本项目混合设备树 |
| 内核头文件发行标识 | `6.8.12-rt-tegra-38.2.0-20260801163300` |
| 相机 | SHW5G（VB1940）接 CAM-3 V6/V7；ZED X Mini（双 AR0234，SN53004639）接 V8 |
| 总线 | CAM-3 为 I²C bus 7，MAX96712 为 `0x49` |

相同内核版本字符串不代表相同厂商 ABI。重建模块必须核对运行内核的配置、头文件、OOT 声明和符号版本，不能强制加载或修改 CRC 绕过不匹配。

## 运行和构建依赖

| 工作 | 依赖 |
| --- | --- |
| PC 控制、回传 | Python 3、SSH 别名 `thor`、rsync |
| Thor 初始化与采集 | Bash、Python 3、sudo、kmod、v4l2-ctl、i2ctransfer、fuser、flock、厂商相机运行库 |
| RGB / 官方深度 | NVIDIA Argus 与 Jetson Multimedia API、型号 ISP、序列号标定、ZED SDK 5.4.1 L4T38.2、CUDA 13、TensorRT 10.13、官方 IMU 辅助进程；检查脚本使用 NumPy、OpenCV Python |
| RGB-D 输出检查与拼接图 | NumPy、OpenCV Python |
| 用户态 C/C++ 编译 | GCC/G++、Make、匹配平台的开发头文件和库 |
| 混合驱动编译 | 匹配内核构建目录、NVIDIA OOT 头文件、经验证的符号版本文件 |
| 设备树编译 | cpp、dtc、fdtoverlay、当前板型 DTS/include |
| IMU 模块编译 | `source/bmi088/`、匹配内核配置/生成头文件/符号表、GCC、Make |

深度使用官方 ZED SDK。SDK 当前使用内置 V4 采集后端，实际并行与独立启停通过，深度表面连续性恢复，实物距离精度尚未标定。项目未要求 ROS 或 GNSS/PTP 服务。aarch64 采集程序不能用 PC 的 x86 二进制替代。

SDK 5.4.1 使用[官方 5.4 下载页](https://www.stereolabs.com/developers/release/5.4)中的 L4T38.2 / JetPack 7.0 CUDA13 发布包，解包在 `evidence/zed-sdk-5.4/extracted`，不替换厂商 BSP。5.4.1 另需 Ubuntu Noble 官方 `libturbojpeg`，当前仅解包到 SDK 旁的 `deps/usr/lib/aarch64-linux-gnu`，通过库搜索路径加载。SDK 需要 `/tmp/imu_daemon.sock`；使用官方驱动包 1.4.2 中的 `IMU_Daemon` 用户态二进制，由 `n10-imu-sdk.service` 启动。仅提取此程序，没有安装其他载板或 L4T38.4 的内核驱动包。部署脚本为 `install_sdk_imu_helper.sh <已核对的官方二进制>`，当前设备已安装。

构建 `build_mixed_n10.sh` 前，按实际资料位置指定以下依赖：

- OOT：与运行内核匹配的 `nvidia-oot` 源码目录，通过 `N10_OOT_ROOT` 指定。
- 符号表：经 ABI 核验的符号版本文件，通过 `N10_VERIFIED_SYMVERS` 指定。
- 当前设备已安装的 `sl_max9295` 和厂商 SHW 相机驱动；`sl_zedx` 从本仓库 `source/stereolabs/zedx/` 构建，包含 N10 共享输出生命周期适配。

SHW 实时 ISP 使用本机 NVIDIA Argus 接口。

## 厂商运行库与调校文件

板级初始化包使用过 `CAM_GEAC_GEAC_A_20260801_2.1.tar.gz`。需要同版本的 `demo/init_demo`、`lib/`、`lib/sensorlib/`、`cfg/hb_j5dev.json` 和配置说明。当前三相机所需文件已部署到 `vendor/shw5g/`，运行不再依赖原 `shw5g-capture` 项目目录。

使用与 V6/V7 SHW、V8 ZED 接线匹配的混合配置，不能用旧单 ZED 初始化器或另一套端口配置替代。板级初始化是建立链路的必要步骤。

| 文件 | 来源与用途 |
| --- | --- |
| [shw5g_vb1940.isp](../calibration/isp/shw5g_vb1940.isp) | 本地 SHW 手册配套 `camera_overrides.isp`；按 SHW 的设备树 badge 加载 |
| [zedx_ar0234.isp](../calibration/isp/zedx_ar0234.isp) | 从 Stereolabs v1.4.4 / R36.4 包提取的文本调校；按 ZED 的设备树 badge 加载 |
| [provenance.json](../calibration/isp/provenance.json) | 调校来源、包版本和 SHA256 |
| [SN53004639.conf](../calibration/SN53004639.conf) | Stereolabs 官方序列号标定服务下载；用于 ZED 几何校正与深度 |

没有将 R36.4 驱动包安装到 R38.2；文本 ISP 的实测可用不代表整个驱动包兼容。混合型号不能共用一个全局 `camera_overrides.isp`。

完整重建还需与运行镜像匹配的主内核、`nvidia-oot`、板厂 `rb` 扩展源码、DTS/include、生成头文件和 `Module.symvers`。收到过的 `Thor_JP7.1_YH_code_20260811.tar.gz` 仅经逐项核对后用于相关声明；包名不能作为 JP7.0/R38.2 兼容依据。

原单 ZED 基础交付 `ZEDX_N10_CAM3_2026-09-16.zip` 包含另行适配的图像驱动、设备树、加载器及 ABI 记录，不随本仓库发布。维护独立 IMU 入口时，还需其中的 `load_zedx_n10.sh` 加载脚本和板级初始化依赖，按实际部署位置配置；仅编译仓库已有 BMI088/SPSC 源码不必再次取得完整 Stereolabs BSP。

继续开发外部触发或绝对授时时，需确认当前端口 MFP 路由、电平、边沿、CPLD 固件/寄存器协议，以及可信时间源。`tztek-jetson-tool-internal-trigger-camera-v1.1.deb` 的协议资料可供核对，当前采集不调用该工具。

## 部署与资料管理

禁止执行系统整体升级，也不要替换为其他载板的内核或设备树。单独安装软件包前检查依赖变化。运行中禁止直接断电；需要关机时先执行 `sudo poweroff`，确认关机后再断电。

厂商运行库、构建产物、完整采集会话和系统备份不提交 Git。新设备需单独提供获授权且版本匹配的依赖。保留源码许可声明、厂商包来源/校验值及启动配置备份。

设备密码、厂商账号、令牌、SSH 私钥及带认证参数的链接不写入代码、文档或日志；受限资料通过授权渠道交接。
