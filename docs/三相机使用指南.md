# N10 三相机使用指南

文中命令在对应设备的仓库根目录执行；相对路径以该目录为起点，`$PWD` 表示当前仓库根目录。

## 型号与接线

天准 N10 `B25EJ21_007 R1.1`，厂商内核 `6.8.12-rt-tegra`，L4T R38.2 / JetPack 7.0；保持 CAM-3 V6/V7/V8 接线。

| 接口 | 型号 | 输出与设备身份 |
| --- | --- | --- |
| V6 | SENSING SHW5G，ST VB1940 | 2560×1984 RGB；RAW 设备 `shw5g_30fps 7-0012`，当前 `/dev/video5` |
| V7 | SENSING SHW5G，ST VB1940 | 2560×1984 RGB；RAW 设备 `shw5g_30fps 7-0013`，当前 `/dev/video6` |
| V8 | Stereolabs ZED X Mini，双 AR0234，SN53004639 | 1920×1200 校正左右 RGB、官方 NEURAL 深度与置信度 |

ZED 出厂基线 49.834557 mm，出厂参数见 [SN53004639.conf](../calibration/SN53004639.conf)。当前管线路由下，光学左目 RAW 为 `7-0028` / `/dev/video4`，右目为 `7-0020` / `/dev/video7`。Argus 索引分别是 ZED 右 0、左 1、SHW V6 2、V7 3。设备节点编号为当前枚举结果；ZED SDK 按序列号打开相机。

两台 SHW 是单目 RGB 相机，没有各自的深度输出。三台相机可并行取图、独立启停，但尚未实现三台曝光同步。

## 实时采集与录制回传

本节使用 `record` 录制和回传文件；在电脑浏览器连续查看画面使用后文的 `live` 实时预览命令。

在开发电脑的仓库根目录执行：

```bash
python3 scripts/capture_remote_n10.py record --initialize --name new-session --frames 600 --save-every 60
```

`--initialize` 在设备空闲时将 N10 时间和时区同步到本机、写入 RTC，然后初始化混合驱动与官方 IMU 辅助服务。设备重启后执行一次；后续采集省略此参数。初始化不能与任何相机采集同时执行。

上例各路预热 90 帧后接收 600 帧，每 60 帧保存一组；逐帧时间戳全部记录。结束后通过 SSH/rsync 回传，两端保存在 `ouputs/new-session/`，SHA256 校验完整会话。目录必须是新名称。断线后续传：

```bash
python3 scripts/capture_remote_n10.py fetch new-session
```

在 Thor 的终端中进入仓库根目录，直接执行：

```bash
sudo python3 scripts/capture_three_n10.py "$PWD/ouputs/new-session" --frames 600 --save-every 60
```

各路 `latest.jpg` 是正在采集的最新保存帧，ZED 另有 `latest-depth.jpg`；均原子替换，更新间隔由 `--save-every` 决定。程序持续采集并保存指定样本，不包含视频网络推流服务器。`--save-every 1` 保存每个已接收帧，实际吞吐受编码和存储限制；SHW 当前 JPEG 写入会造成接收间隔增大，不能承诺无丢帧 30 fps 录像。

## 独立启停

在两个 Thor 终端启动不同相机集合：

```bash
sudo python3 scripts/capture_three_n10.py "$PWD/ouputs/zed-only" --cameras zed --frames 10000 --save-every 60
sudo python3 scripts/capture_three_n10.py "$PWD/ouputs/shw-only" --cameras shw_v6 shw_v7 --frames 10000 --save-every 60
```

Ctrl+C 或 SIGTERM 只停止该命令管理的相机。SHW V6/V7 也可分为两个命令分别控制。同一相机重复占用会被拒绝；需要逐路停止时使用独立进程，不停止管理全部三路的同一个命令。

三路共用 CAM-3 MAX96712 和 CSI 输出。驱动用共享使用计数维护输出，仅最后一路停止时关闭公共输出；程序只串行化打开/关闭及预热，正常取图并行。共享硬件故障、全局服务重启和驱动重载仍可能影响所有相机，不能当作互相隔离的操作。

硬件交叉启停验收入口：

```bash
sudo python3 scripts/validate_three_restart_n10.py "$PWD/ouputs/new-independence-test"
```

逐路停止和重启，要求其他路继续收到新帧；测试设置与结果见 [三相机验收说明](三相机验收说明.md)。

## 电脑实时预览

在开发电脑的仓库根目录执行，浏览器自动打开本机预览页。`--cameras` 与录制命令使用相同名称，只打开所选相机；省略时打开全部三路。

```bash
# 全部三路：两路 SHW RGB + ZED RGB、深度
python3 scripts/capture_remote_n10.py live

# 单独使用 ZED：RGB 左目 + 官方深度显示图
python3 scripts/capture_remote_n10.py live --cameras zed

# 单独使用 SHW：每台仅显示 RGB
python3 scripts/capture_remote_n10.py live --cameras shw_v6
python3 scripts/capture_remote_n10.py live --cameras shw_v7

# 选择多路
python3 scripts/capture_remote_n10.py live --cameras shw_v6 shw_v7
python3 scripts/capture_remote_n10.py live --cameras shw_v7 zed
```

默认网址为 `http://127.0.0.1:8844/`。页面显示每路状态、预览输出帧率和浏览器显示帧率，支持放大画面。启动时先完成相机预热。ZED 的 RGB 和深度来自同一次 SDK 采集，在同一个预览包中传输和更新。

### 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--cameras` | `shw_v6 shw_v7 zed` | 单路或多路选择，名称不能重复 |
| `--preview-fps` | `10` | 预览发布上限，1–30 fps；实际速率由编码和网络决定 |
| `--preview-width` | `960` | 偶数宽度，320–1920，保持原图比例 |
| `--port` | `8844` | 电脑本地端口；0 自动选择空闲端口 |
| `--no-browser` | 不启用 | 仅打印网址，自行打开浏览器 |
| `--duration` | `0` | 所选相机完成启动尝试后的运行秒数；0 持续运行 |
| `--initialize` | 不启用 | 在全部相机/IMU 空闲时复用原初始化流程 |

```bash
python3 scripts/capture_remote_n10.py live --cameras shw_v7 zed --preview-width 640 --preview-fps 15 --port 8845
```

使用其他已配置 SSH 别名时，将全局参数放在 `live` 前：

```bash
python3 scripts/capture_remote_n10.py --host thor live --cameras zed
```

Thor 重启后的第一次使用可以加 `--initialize`。已有任何一路运行时，启动其他路应省略该参数。

### 并行使用

不同相机集合可以在不同终端运行。两个实时会话使用不同本地端口：

```bash
# 开发电脑终端 1：SHW 两路实时 RGB
python3 scripts/capture_remote_n10.py live --cameras shw_v6 shw_v7 --port 8844

# 开发电脑终端 2：ZED 实时 RGB-D
python3 scripts/capture_remote_n10.py live --cameras zed --port 8845
```

也可以在 SHW 预览期间，仅录制 ZED 原始数据：

```bash
python3 scripts/capture_remote_n10.py record --cameras zed --name new-zed-session --frames 300 --save-every 10
```

同一相机只能被一个会话占用；需要录制已在预览的相机时，先停止管理该相机的预览命令。全局初始化、服务重启和驱动重载会影响共享硬件。

### 图像处理与退出

| 项目 | SHW V6 / V7 | ZED X Mini |
| --- | --- | --- |
| 采集与处理 | 复用 Argus 和型号 ISP，缩小后的 NV12 图像转换为 JPEG | 复用官方 SDK 的校正 RGB 和 NEURAL 深度显示图 |
| 默认预览尺寸 | 每台 960×744 RGB | RGB、深度各 960×600 |
| 预览更新 | 独立编码，只发布最新帧 | 同帧 RGB 和深度成对发布 |
| 原始数据录制 | 使用原 `record` 入口保存完整尺寸 RGB | 使用原 `record` 入口保存完整尺寸左右 RGB、米制深度和置信度 |

预览频率独立于录制保存间隔。预览只保留最新图像，编码或网络变慢时不累计历史帧。纯预览不保存连续图片、原始深度或逐帧 CSV，临时会话退出后清理。

Ctrl+C 停止本命令管理的相机及 SSH 转发。关闭或刷新浏览器不会重新打开相机，也不会停止终端会话。画面停滞、相机异常或连接断开会在页面标明；会话已退出时需重新运行命令。电脑控制进程退出、SSH 输入关闭或 15 秒没有心跳时，Thor 停止本次会话。

电脑通过现有 SSH 连接访问 Thor 的本机预览服务。电脑端使用 Python 标准库和 SSH；Thor 使用已有 SDK、Argus 与 OpenCV。深度显示图仅用于观察，数值检查使用原始 float32 深度。

状态检查：

```bash
curl --noproxy '*' http://127.0.0.1:8844/api/status
```

`age_ms` 表示 Thor 采集进程收到画面后的帧年龄，不等于完整的曝光到屏幕显示延迟。

## 拍摄与 RGB 处理

| 项目 | SHW V6 / V7 | ZED X Mini |
| --- | --- | --- |
| 接口 | NVIDIA Argus 实时 ISP | 官方 ZED SDK 5.4.1 / L4T38.2 |
| 分辨率 / 请求帧率 | 2560×1984 / 30 fps | HD1200 1920×1200 / 30 fps |
| 曝光 / 增益 | 7500 μs，模拟及 ISP 增益 1× | SDK 自动曝光与自动增益 |
| 白平衡 | ISP 自动白平衡 | SDK 自动白平衡 |
| 预热 | 90 帧 | 90 帧 |
| 颜色输出 | 型号 ISP → Argus JPEG 输出 | SDK `VIEW::LEFT/RIGHT` 校正图，直接保存 PNG |

SHW 使用厂商 `shw5g_vb1940.isp`；ZED 使用 Stereolabs `zedx_ar0234.isp`，由不同设备树 badge 选择。禁止用一个全局 `camera_overrides.isp` 覆盖混合型号。来源和哈希见 [ISP provenance](../calibration/isp/provenance.json)。去马赛克、颜色矩阵和色调处理由对应 ISP/SDK 完成，不叠加旧软件白平衡、颜色矩阵或 gamma。

采集脚本设置 `ZED_SDK_VIDEO_CAPTURE_VERSION=4`，使用同一官方 SDK 内置的 V4 后端；这是当前设备实测配置，不是对所有载板的通用保证。深度由官方 SDK 计算。

参考照片仅用于同一图案位置的蓝、绿、白、背景和灯带颜色检查，不参与改色；手机照片也不等于标准色卡。饱和灯带中的纹理无法由后处理恢复。

## 官方深度

依据官方 [深度 API](https://docs.stereolabs.com/docs/development/zed-sdk/modules/depth-sensing/using-the-api) 和 [相机控制](https://docs.stereolabs.com/docs/development/zed-sdk/modules/camera/camera-controls)：

- 同一次 `grab()` 读取校正左 RGB、`MEASURE::DEPTH` 和 `MEASURE::CONFIDENCE`，像素坐标一致；不重复做 OpenCV 校正。
- NEURAL，深度稳定参数 30，单位米，范围 0.2–4 m；置信度阈值 95、纹理阈值 100，关闭填洞，`remove_saturated_areas=false`。
- 深度是沿左相机光轴的 Z，保存 float32 NPY，保留 NaN/Inf。置信度越低越可信。范围设置不代表距离精度保证。
- `VIEW::DEPTH` 和彩色预览仅用于显示。固定范围预览中黑色表示无效测距，不是零米。

当前已取得官方 RGB、深度和置信度。默认固定为官方 SDK 5.4.1，当前场景有效深度约 63%。纸张与隔板已恢复连续表面，仍保留无效区域，绝对距离精度未做实物标定。`run.json` 的 `status=checked` 仅表示采集、文件和双目几何检查通过，`depth_accuracy_verified=false` 明确保留；不得据此声称 RGB-D 距离正确。

## 输出文件

| 文件 | 内容 |
| --- | --- |
| `run.json`、各路 `.log` | 运行结果、SDK 后端、帧率与间隔、几何和深度有效比例、日志 |
| `shw_v6/`、`shw_v7/` | RGB JPEG、`latest.jpg`、逐帧 CSV、完成标记 |
| `zed/*-left.png`、`*-right.png` | SDK 校正左右 RGB |
| `zed/*-depth-m.npy`、`*-confidence.npy` | 原样保留的官方 float32 深度及置信度 |
| `zed/*-sdk-depth-view.png`、`latest-depth.jpg` | SDK 深度显示图 |
| `zed/init.json`、`runtime.json`、`calibration.json` | SDK 实际初始化、运行和校正标定参数 |
| 各路 `frames.csv` | 图像时间戳、主机单调时钟、曝光、增益、白平衡、是否保存 |
| `SESSION-SHA256SUMS` | 完整会话校验清单 |

```python
import cv2
import numpy as np
rgb_bgr = cv2.imread('zed/0-left.png')
depth_m = np.load('zed/0-depth-m.npy', allow_pickle=False)
valid = np.isfinite(depth_m) & (depth_m > 0)
```

按实际文件名读取；各路独立启动，编号相同不表示同时曝光。N10 系统时钟已按 PC 同步。SHW 传感器时间戳与 SDK 图像时间戳属于不同时间域，不能直接相减；跨进程连续性观察使用同机 `host_monotonic_ns`，这不代表曝光同步。

## 构建与离线检查

Thor 项目根目录构建：

```bash
bash scripts/build_mixed_n10.sh
export ZED_DIR="$PWD/evidence/zed-sdk-5.4/extracted"
bash scripts/build_three_n10.sh
python3 scripts/configure_native_isp.py check
```

`build_three_n10.sh` 构建 `capture_shw_n10` 和 `capture_zed_n10`。当前部署使用 `mixed_sdk` 启动项和 `/boot/dtb/n10-cam3-mixed-sdk.dtb`。混合初始化加载适配驱动及官方 IMU 辅助服务，保留原启动项与备份。

实时预览另构建 `capture_shw_live_n10`，与 SHW 录制程序共用采集源码；其构建使用设备已有的 OpenCV C++ 头文件和库。ZED 实时与录制共用 `capture_zed_n10`。

官方 SVO 离线检查，不打开相机：

```bash
bash scripts/analyze_zed_svo_n10.sh input/capture.svo2 "$PWD/ouputs/new-svo-check"
```

将 `input/capture.svo2` 替换为待检查的 SVO 文件路径。处理前 120 帧，每 30 帧保存 RGB、深度预览与指标；输入至少 120 帧。默认使用 SDK 5.4.1。

参考图检查与拼接：

```bash
python3 scripts/analyze_three_n10.py ouputs/new-session reference.jpg points.json ouputs/new-reference-check
```

使用 `--reviewed-points` 时，采样坐标须绑定对应图像 SHA256。参考照片用于对应图案颜色检查，不提供距离真值。

依赖见 [开发依赖与资料清单](开发依赖与资料清单.md)，测试设置与结果见 [三相机验收说明](三相机验收说明.md)。`validation/` 保留原仓库数据，当前输出放在 Git 忽略的 `ouputs/`。

## 棋盘深度检查

使用已知尺寸、平整且完整可见的棋盘，沿用 ZED 原始数据录制和回传。以下例子为 12×9 个方格、单格 25 mm，对应 11×8 个内角点：

```bash
# 开发电脑：仅录制 ZED，SHW 可继续使用；不要重复初始化
python3 scripts/capture_remote_n10.py record --cameras zed --name new-board-session --frames 300 --save-every 10

# Thor 仓库根目录：离线分析；输入和输出目录按实际会话填写
python3 scripts/check_checkerboard_depth.py ouputs/new-board-session ouputs/new-board-analysis --cols 11 --rows 8 --square-mm 25 --front-distance-mm 360
```

采集和分析输出目录均须使用新名称。`--cols`、`--rows` 填内角点数，`--square-mm` 填单格边长，`--front-distance-mm` 记录相机外壳前端到板面的实测距离。

分析复用 SDK 保存的左右校正图、米制深度、置信度和相机参数，检测角点、检查左右对应、拟合板面，并统计有效深度比例、平面残差、黑白格中部差异及静态时间波动。内部采样避开棋盘边缘、背景和黑白交界。已知棋盘尺寸的图像位姿估计作为辅助参照，与 SDK 深度共享相机内参。

| 分析文件 | 内容 |
| --- | --- |
| `summary.json` | 设置、逐帧结果、汇总指标及参考距离 |
| `metrics.csv` | 逐帧深度、平面与角点指标 |
| `corners.json`、`corners-left.jpg` | 左右角点坐标与检测标注 |
| `overview.png` | 角点图、板面深度、平面残差和时间曲线 |
| `temporal-jitter.png` | 固定采样区域的逐像素时间标准差 |

外壳前端尺量与相机光学原点需要对齐，才能将差值作为绝对测距误差。不同位置的深度变化可用于检查距离变化响应；静态波动和平面残差分别反映重复性和平面重建质量。

回归检查：

```bash
# Thor：处理、文件校验、实时会话和棋盘计算测试
python3 -m unittest discover -s tests -v

# 开发电脑：有 Node.js 时运行页面选择与绘图调度测试
node tests/test_live_preview_ui.js
```

实时预览、录制回归及两位置棋盘测试的设置与结果见 [三相机验收说明](三相机验收说明.md)。
